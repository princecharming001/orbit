## 2. System prompt prefix and prompt caching (`chat/agent/system.ts`)

- `systemBlocks(nonce, knowledge)` (`system.ts:252-259`) returns three text blocks: (1) `stableSystemText()` - the concatenation of 17 frozen rule sections (`:224-244`), **with `cache_control: {type:'ephemeral'}`**; (2) the student's playbook `knowledge` block (`chat/agent/knowledge.ts:10-20` → `packages/core/src/knowledge/index.ts:177-189`: etiquette + the sections for the student's active goals/target functions; each `.md` section is 3-5 KB, `packages/core/src/knowledge/*.md`), **no cache_control**; (3) `untrustedRule(tag)` with the per-conversation nonce (`chat/agent/store.ts:36-40`, derived from the conversation id), no cache_control.
- Request order is tools → system → messages. Tools: `buildRunnerTools` sorts the registry by name and puts `cache_control` on the last client tool (`loop.ts:133-135,222-223`); `withWebSearch` strips that and puts the breakpoint on the trailing `web_search` tool instead (`:228-231`); the request also carries a top-level `cache_control: ephemeral` (`:256`). So the cached prefix is **[all tools + web_search] + [stable system block]**; the knowledge block and nonce block ride on the final (top-level) breakpoint together with the messages.
- Stability: the tools and block (1) are byte-identical for every conversation of every student whose tool registry is identical (the registry is built per app from `chat/registry.ts`/`capabilities.ts`; cohorts with different capabilities - demo, account, local - may differ; not verified here). Block (2) changes only when the student's goals change (`knowledge.ts:3-5`), so it stays warm within a conversation but is **per-student**, so the shared cache ends at block (1) for cross-user hits. Block (3) is per conversation. Prompt-cache hits also require the same API key: own-key users have their own cache; shared-proxy users share the proxy's key. Ephemeral TTL is the API default (5 min) - not configured in code.
- Volatile context is kept out of `system`: the snapshot (`chat/agent/snapshot.ts`) is appended to `messages` as a `role:'system'` row only when its key changed or the Remembered line changed (`loop.ts:323-338`), so the prefix is not invalidated per turn. `STABLE_SYSTEM_VERSION = 24` (`system.ts:34`); any text change recreates the cache for everyone once.
- Token accounting treats cache reads at 1/10 (`anthropic.ts:377-383`); stored per message (`loop.ts:267-274,463`).

## 6. Duplicate-lookup risks

1. **Same person, two Orbit rows** - mutuals (`mutuals3:` keyed by Orbit `personId`, `linkedinLive.ts:866`), enrichment records (`enrich:rec:{personId}`), photo `tried` and `memberid:tried` are all keyed by Orbit person id, so an unmerged duplicate (same LinkedIn member) is looked up twice. In-flight dedupe for mutuals is by `accountId|memberId` (`:807`) but the day cache is not.
2. **Profiles read by three ledgers** - enrichment `/profile` (`index.ts:238`, record `profileAt`), hop evidence `/profile` (`hopEvidence.ts:76`, `engagement.profileAt`, skipped only when `person.linkedinFollowers` is set or the engagement row is <30 d), and photo `/photo` (`photoQueue.ts:146`, skips only when `profileAt` <45 d). A photo-only read never updates `enrich:rec`, so an expired photo can be refreshed by the photo queue **and** by enrichment's `photo_refresh` need (`index.ts:171-172`) in the same day. Enrichment's search-verify reads of candidate profiles (`index.ts:355-367`) are not recorded against any person.
3. **Companies fetched by two queues** - `logoQueue` `/companies` by raw name batch (`logoQueue.ts:155`, excludes orgs that already have `logoUrl && linkedinCompanyId`, `:102-105`) and enrichment `refreshLogos` `/company` by id/slug (`logos.ts:77`, asks when `logoDue`: id known but no/expired logo). ## Answers to the specific questions

### (1) Caps and keys in `orbit-claude/proxy.ts`, where they are stored, and the 400 "credit balance too low"

Values (all in `orbit-claude/proxy.ts` unless noted; env overrides in `orbit-claude/index.ts`):
- Per user per UTC day: `DEFAULT_CAP_USD = 20` (line 79; `capUsd: num('ORBIT_USER_CAP_USD', 20)` index.ts:20). Subject key = `subjectOf()` + `:<YYYY-MM-DD>` (lines 321-335, 524-525): `user:<uuid>:<day>` for a valid `x-orbit-session` HS256 token, else `client:<id>:<day>` for a well-formed `x-orbit-client` (16-64 chars, line 261), else `ip:<sha256(salt:ip)[0:32]>:<day>` (495). Check `spent >= cap` at 563 → 429 `x-orbit-limit: budget`.
- Anonymous (no signed-in session): `DEFAULT_ANON_IP_DAILY_USD = 10` (85; env `ORBIT_ANON_IP_DAILY_USD`), key `ipday:<visitor>:<day>` (528), checked at 555; charged in addition to the client/ip subject (529, 611).
- Global per day: `DEFAULT_GLOBAL_DAILY_USD = 200` (87; env `ORBIT_GLOBAL_DAILY_USD`), key `global:<day>` (527), checked at 544.
- Request counters (not dollars): `DEFAULT_LIMITS` 72-77 = 120/visitor/minute, 5,000/visitor/day, 100,000 global/day; per call type `DEFAULT_CALL_PER_DAY` 66-71 (memory 3000, resume 50, rapport 3000, judge 5000). Keys `orbit:min:<minute>:<visitor>`, `orbit:day:<day>:<visitor>`, `orbit:global:<day>`, `orbit:<call>:<day>:<visitor>` (238-258). Bug worth knowing: the over-limit classifier at line 507 matches `memory|resume|rapport` only, so an exhausted `judge` bucket is reported as `x-orbit-limit: day`, not `call`.
- Lifetime: **there is no lifetime cap in proxy.ts.** The lifetime cap is `USER_TOTAL_USD = 100` in `_shared/budget.ts:48`, enforced only by `checkBudget` for server tasks (101-113). It tries to include chat spend by reading `public.orbit_proxy_spend where subject = 'user:<uuid>'` (budget.ts:103), but the proxy writes day-suffixed subjects (`user:<uuid>:<day>`, proxy.ts:525), so that lookup never matches a row: **chat spend is not counted in the $100 lifetime cap as the code stands.** Symmetrically, `orbit_spend_total` (migration `20261016_orbit_spend_cap.sql` 31-34) adds `usage_ledger` only when the subject matches `^user:[0-9a-fA-F-]{36}$`, which a day-suffixed subject never does, so the proxy's per-day $20 counts chat only, never server-task spend.
- Storage: dollars in `public.orbit_proxy_spend(subject text pk, usd numeric(12,5), requests int, first_at, updated_at)` via `orbit_spend_add(p_subject, p_usd)` / `orbit_spend_total(p_subject)` (migration 20261016 lines 8-51; proxy `postgrestSpend` 619-639, amounts rounded to 5 dp at 636). Counters in `public.orbit_proxy_counters(bucket text pk, count int, expires_at)` via `orbit_proxy_take` (migration `20261012_orbit_claude_proxy.sql` 4-43). The key itself: env `ORBIT_ANTHROPIC_API_KEY` or `orbit_private.secrets` through `orbit_secret()` (migration 20261012 lines 49-67; proxy `postgrestSecret` 669-693, 5-minute memo).
- Allowed models per call type: `rejectBody` (172-200) admits `claude-opus-5-5` or `claude-haiku-5-5` for any call, `fallbacks` only `claude-opus-5`, `max_tokens` 1..16000, no `mcp_servers`/`container`/`service_tier`/`inference_geo`, tools only `custom` plus `web_search_20260209` with `max_uses` 1..5; `rejectCall` (210-222) refuses Haiku for `chat` and, for the other four types, enforces `CALL_LIMITS` (49-56), no tools, no thinking, exactly one message.
- Prompt caching passthrough / streaming: the body is forwarded as-is (585); `meter` (350-438) reads usage from SSE `message_start`/`message_delta` or from the JSON body, prices cache read/write tokens with `prices.ts` and web searches at $0.01 each; nothing else is rewritten.
- A 400 from Anthropic (including "credit balance is too low"): the proxy makes exactly one upstream request (582-587) and **does not retry**; any non-ok status other than 401/403 is passed through to the browser with its body and the `request-id`/`retry-after`/`x-should-retry` headers (591-596, 605-607), **not metered** (meter wraps only `upstream.ok` bodies, 606). It **is counted** in the request counters, because `take` ran at 498 before the upstream call. 401/403 are rewritten to 503 `unconfigured` (598-604). Whether the browser's Anthropic SDK retries is not in this repo; the Anthropic SDKs retry 408/409/429/5xx and connection errors with `maxRetries` 2 by default, not 400 (SDK behaviour, not repo code). For server tasks, `claude.ts` uses the SDK with `maxRetries: 2` (121): a 400 is not retried, surfaces as `{error:'api_error'}` (161-167), and no `usage_ledger` row is written because `recordUsage` runs only after a response (170-177); the `checkBudget` read before it is not refunded (nothing was charged).

## 3. Enqueue fan-out for 1, 10 and 100 users

Assumptions stated per row; N = users; each user has Google (gmail+calendar scopes) and LinkedIn active; no Gmail Pub/Sub watch (plan 26 reports none set, `docs/plan/26-cost-and-speed.md:17`); P = people per user (score pages = ⌈P/300⌉, P = 1,000 assumed → 4). Scheduled work only; event-driven kinds (classify, score.person, send, dossier, hop, source) come on top.

|---|---|---|---|---|
| `sync.gmail.incremental` poll (`orbit-incremental`) | 72-144 N (10-min slots, every other slot suppressed by `last_synced_at`) | 72-144 | 720-1,440 | 7,200-14,400 |
| `sync.calendar` poll | 72-144 N | 72-144 | 720-1,440 | 7,200-14,400 |

Measured corroboration (2 users, 2026-10-26, before the tick guard): 1,437 worker invocations/day, 694 job runs/day of which 557 `sync.gmail.incremental` and 95 `sync.calendar` at 4.8 s (`docs/plan/26-cost-and-speed.md:15-17`).

Unipile daily reads per account from scheduled work: census ≤40 search pages, reading ≤30 profiles + ≤90 company pages (shared), plus whatever the browser spends of the same ledgers. Claude from scheduled work per user per day, upper bound: `search_reading` ≤72 Haiku `reading`; `cadence.user` Opus composes = number of bump/thank-you/nurture actions + ≤3 first touches + Sonnet judges; `voice.distill` ≤1 Opus; `classify.message` 0-2 Haiku + 0-2 Opus per inbound message. The caps that bound this: `$1.50/day` and `$25/month` anthropic per user (`budget.ts:22,43`).

Capacity note: a tick runs jobs sequentially within ≤110 s and at most 3 heavy jobs; overlapping ticks are separate invocations sharing pgmq visibility. At N=100 the two polls alone are ~29 jobs/min; at the measured 4.8 s per calendar poll that is ~140 s of work per minute, more than one tick, so the polls would queue behind each other and `sync.linkedin`/heavy work would starve. This is arithmetic from the constants, not a measurement.

## 4. Ready-to-run SQL (select only)

```sql
-- 4.1 Spend per provider per day, last 14 days (server tasks)
select (created_at at time zone 'utc')::date as day, provider,
       count(*) as calls, sum(units) as units, round(sum(cost_usd), 4) as usd,
       count(distinct user_id) as users
  from orbit.usage_ledger
 where created_at >= now() - interval '14 days'
 group by 1, 2 order by 1 desc, 5 desc;

-- 4.1b the same by provider + operation (Claude task names are in operation)
select (created_at at time zone 'utc')::date as day, provider, operation,
       count(*) as calls, round(sum(cost_usd), 4) as usd
  from orbit.usage_ledger
 where created_at >= now() - interval '14 days'
 group by 1, 2, 3 order by 1 desc, 5 desc;

-- 4.2 Chat proxy spend per user per day (subjects are '<kind>:<id>:<YYYY-MM-DD>')
select split_part(subject, ':', 3) as day,
       split_part(subject, ':', 1) as kind,
       split_part(subject, ':', 2) as id,
       usd, requests, updated_at
  from public.orbit_proxy_spend
 where subject ~ ':\d{4}-\d{2}-\d{2}$'
   and split_part(subject, ':', 3)::date >= current_date - 14
 order by 1 desc, usd desc;

-- 4.2b global and anonymous-IP daily totals
select subject, usd, requests from public.orbit_proxy_spend
 where subject like 'global:%' or subject like 'ipday:%'
 order by subject desc limit 60;

-- 4.3 Job runs per kind per day with status and average duration
select (started_at at time zone 'utc')::date as day, kind, status,
       count(*) as runs, round(avg(duration_ms)) as avg_ms, max(duration_ms) as max_ms,
       count(distinct user_id) as users
  from orbit.job_runs
 where started_at >= now() - interval '14 days'
 group by 1, 2, 3 order by 1 desc, 4 desc;

-- 4.4 Dead or retried runs per kind (attempt > 1 means the message had been read before)
select kind,
       count(*) filter (where attempt > 1) as retried_runs,
       count(*) filter (where status = 'error') as errors,
       count(*) filter (where status = 'error' and error = 'died with the isolate') as isolate_deaths,
       count(*) filter (where status = 'skipped') as skipped,
       max(attempt) as max_attempt
  from orbit.job_runs
 where started_at >= now() - interval '14 days'
 group by 1 order by 2 desc;

select (created_at at time zone 'utc')::date as day, queue, message->>'kind' as kind, count(*), min(error)
  from orbit.dead_letters
 where created_at >= now() - interval '30 days'
 group by 1, 2, 3 order by 1 desc;

-- 4.4b skipped reasons (duplicate / user_gone / unconfigured / not_connected / needs_reauth ...)
select kind, error as reason, count(*)
  from orbit.job_runs
 where status = 'skipped' and started_at >= now() - interval '14 days'
 group by 1, 2 order by 3 desc;

-- 4.5 Cron job list with schedule and last runs
select jobid, jobname, schedule, command, active from cron.job order by jobname;

select j.jobname, d.status, count(*) as runs,
       round(avg(extract(epoch from (d.end_time - d.start_time))), 2) as avg_sec,
       max(d.start_time) as last_start
  from cron.job_run_details d join cron.job j on j.jobid = d.jobid
 where d.start_time >= now() - interval '7 days'
 group by 1, 2 order by 1, 2;

-- 4.6 pgmq queue depth and archive counts
select * from orbit.queue_depth();            -- depth, visible, oldest_age_sec per queue
select queue_name, queue_length, newest_msg_age_sec, oldest_msg_age_sec, total_messages
  from pgmq.metrics_all();
select 'orbit_send' q, count(*) from pgmq.a_orbit_send
union all select 'orbit_classify', count(*) from pgmq.a_orbit_classify
union all select 'orbit_sync',     count(*) from pgmq.a_orbit_sync
union all select 'orbit_cadence',  count(*) from pgmq.a_orbit_cadence
union all select 'orbit_score',    count(*) from pgmq.a_orbit_score
union all select 'orbit_enrich',   count(*) from pgmq.a_orbit_enrich;

-- messages read many times but never finished (read_ct climbs without the row being deleted)
select 'orbit_sync' q, msg_id, read_ct, enqueued_at, message->>'kind' kind, message->>'userId' user_id
  from pgmq.q_orbit_sync where read_ct > 1
union all
select 'orbit_enrich', msg_id, read_ct, enqueued_at, message->>'kind', message->>'userId'
  from pgmq.q_orbit_enrich where read_ct > 1
order by read_ct desc;

-- 4.7 Research cache hit rate (steps carry cached:true; see research/web.ts:290-299)
with s as (
  select r.created_at, r.kind, r.status, r.cost_usd, st
    from public.orbit_research_runs r, jsonb_array_elements(r.steps) st
   where r.created_at >= now() - interval '30 days'
     and (st->>'step') like '%search%'
)
select (created_at at time zone 'utc')::date as day, kind,
       count(*) as search_steps,
       count(*) filter (where (st->>'cached')::boolean) as cached,
       round(100.0 * count(*) filter (where (st->>'cached')::boolean) / nullif(count(*), 0), 1) as hit_pct
  from s group by 1, 2 order by 1 desc;

select (created_at at time zone 'utc')::date as day, kind, status, count(*), round(sum(cost_usd), 4) usd,
       round(avg(ms)) avg_ms
  from public.orbit_research_runs
 where created_at >= now() - interval '30 days'
 group by 1, 2, 3 order by 1 desc;

select kind, count(*) rows, count(*) filter (where expires_at > now()) live
  from public.orbit_research_cache group by 1;

-- the per-user Exa / hop cache (orbit.research_cache): rows by provider, live vs expired
select provider, count(*) rows, count(*) filter (where expires_at > now()) live
  from orbit.research_cache group by 1;

-- 4.8 profile_reads and company_pages per day
select (read_at at time zone 'utc')::date as day, read_by, status,
       count(*) as reads, count(distinct user_id) as users,
       count(*) filter (where reading_at is not null) as read_by_model,
       count(*) filter (where reading_model is not null) as model_calls_recorded
  from orbit.profile_reads
 where read_at >= now() - interval '14 days'
 group by 1, 2, 3 order by 1 desc;

select (read_at at time zone 'utc')::date as day, status, count(*) as pages,
       count(*) filter (where reading_at is not null) as read_by_model
  from orbit_private.company_pages
 where read_at >= now() - interval '14 days'
 group by 1, 2 order by 1 desc;

-- 4.9 LinkedIn ledger use today per account (the shared counters)
select bucket, count, expires_at
  from public.orbit_proxy_counters
 where bucket like 'connectors:li:%' and expires_at > now()
 order by bucket;

-- 4.10 census progress and people with/without a read
select c.user_id, c.seen, c.matched, c.cursor is not null as in_progress, c.pass_started_at, c.pass_done_at, c.last_error
  from orbit.search_census c;

-- 4.11 health snapshots (every 15 min) for the last day
select created_at, details->>'orphaned_runs' orphaned, details->>'job_errors_24h' errors_24h,

-- 4.12 the existing cost view
select * from orbit.v_costs where day >= current_date - 14 order by day desc, cost_usd desc;
```
